# Plan: 让平台业务用户通过 data-api 查询台以受控只读方式查询多数据源，同时把 data-api 迁移到 Spring Boot 3 / JDK 17 脱离 DS 反应堆

**Complexity:** Large — 迁移（框架/依赖/注解体系）+ 新子系统（注册表、查询台前后端）+ 存储切换（线上 PG），多消费者接口必须先定契约。

## Goal

Enable 平台业务用户 to 在 data-api 查询台对授权数据源执行受控只读 SQL 并导出结果 so that 无需运维桌面工具即可完成日常数据查询；同时 data-api 以 Boot 3 独立构建，不再被 DS 3.4.3（Boot 2.x / Java 8）绑死。

## 基线事实（已实测核对）

- 耦合面与方案 §3.1 完全一致：19 个 DS 外部类 import、`@Import({DaoConfiguration, CommonConfiguration})`、`@PostConstruct`×4 / `@PreDestroy`×2（`javax.sql.DataSource` 保留）。
- DS 根 pom 第 61 行 `<module>dolphinscheduler-data-api</module>`；`dolphinscheduler-dist` 不引用 data-api → 反应堆移除无连带破坏。
- `~/.m2` 已具备 `spring-boot-starter-parent:3.0.13`、`magic-api-servlet-jakarta:2.2.2`；JDK 17 位于 `/usr/lib/jvm/java-17-openjdk-amd64` → 可离线构建与冒烟。
- data-api 共 36 个 Java 文件，5 张自有表由 `DataApiSchemaBootstrap` 幂等创建。
- 先例：`17e1c989` data-asset 已按"脱离反应堆 + 独立 JDK 构建"落地，构建/启动脚本模式可复用。

## Deliverables

- Build 契约: `dolphinscheduler-data-api/pom.xml` 换 parent `spring-boot-starter-parent:3.0.13`、`java.version=17`；magic-api 排除 `magic-api-servlet-javaee`；显式锁 H2 2.2.220；新增 postgresql / commons-codec / jsqlparser 依赖 → 使 data-api 可独立 `mvn package` 出可执行 jar。
- 反应堆变更: `dolphinscheduler/pom.xml` 删除 data-api 模块声明 → 拆分两条构建线。
- 只读访问层（新包 `dataapi.meta`）: `User`/`Session`/`DsDataSource` 实体 + JdbcTemplate 仓库（t_ds_user / t_ds_session / t_ds_datasource / t_ds_access_token / t_ds_relation_datasource_user）；`UserType`/`Flag`/`DbType` 枚举；MD5 摘要与 base64+salt 口令解码工具 → 替换全部 19 个 DS 类，移除 MyBatis。
- 生命周期替身: 内置极简 `ServerLifeCycle` 与默认异常处理器，替换 `ServerLifeCycleManager`/`DefaultUncaughtExceptionHandler`；删除 `DaoConfiguration`/`CommonConfiguration` @Import。
- 类型描述符: `resources/datasource-types.yaml`（driver/urlTemplate/quote/limitOffset/catalogMode/readOnlyTx/metadataStrategy/systemSchemas），首批 postgresql + mysql → 新增数据源类型不改 Java。
- 注册表服务: `DataSourceRegistry` 读 DS 源 + 授权过滤 + `da_datasource_ext` 治理字段，按描述符懒建池（池上限 3~5/源）；`DsMagicDataSourceLoader` 改为注册表驱动 → magic 与查询台共用同一注册表。
- 扩展表: `da_datasource_ext`、`da_console_query_log` 由 `DataApiSchemaBootstrap` 幂等建表（7 张表口径）→ 满足存储验收 §9.3。
- 查询台 API: `POST /data-api/console/execute|cancel|export`、`GET /data-api/console/datasources|history`，`console.enabled` 开关默认 false → 查询台后端能力面。
- 七层护栏: 身份 401 / 源授权 403 / JSqlParser 语句守卫 / 只读连接+只读事务 / 1000 行展示·10 万行导出·60s 超时·20KB SQL·单用户并发 1 / 全量审计（含拒绝）/ 用户维度限流 → 方案 §7.2。
- 前端: `dolphinscheduler-ui/src/views/data-api/console/`（数据源选择、CodeMirror SQL 编辑器、Ctrl+Enter 运行/取消、结果网格、CSV 导出、历史侧栏）+ 路由/菜单/i18n → 业务用户可视入口。
- 脚本/文档: `deploy/local/*` 与 `~/ds-run/start-data-api.sh` 口径调整为独立 JDK 17 构建启动 + 健康检查；`docs/DATA-API-BOOT3-CONSOLE-PLAN.md` 记录实测偏差修正。

**Out of scope（继承方案 §1.2）:** DML/DDL、表设计器/数据行编辑、会话锁诊断、列级脱敏、data-asset 共享注册表、外部 DBA 平台、生产 profile 启用查询台。

## Acceptance Criteria

```
AC-1  [构建/启动]   Given 干净工作区, When JDK17 `mvn -f dolphinscheduler/dolphinscheduler-data-api/pom.xml package` 且 `java -jar` 启动, Then 12346 端口就绪、无 javax/Boot2 类冲突、/magic/web 可登录并执行一条查询（P0 Go/No-Go）。
AC-2  [回归-身份]   Given DS 用户/Access Token/会话三种凭据, When 调用 data-api 受保护接口, Then 登录识别与 401/403 行为与迁移前一致；禁用用户被拒。
AC-3  [回归-治理]   Given 迁移后的 ACL/审计/限流/发布链路, When 执行方案 §9.1 的 8 项回归, Then 全部通过（限流 429、审计成对落 da_api_invoke_log、发布/回滚各一次）。
AC-4  [正向查询]    Given 已授权 PG 或 MySQL 源, When 执行单条 SELECT/WITH/EXPLAIN, Then 返回列+行+耗时，>1000 行时 truncated=true；取消生效；导出 CSV ≤10 万行。
AC-5  [拒绝路径]    Given 未登录/未授权源/update/delete/create/多语句/FOR UPDATE/pg_sleep/超长 SQL/并发第 2 条, When 提交, Then 分别 401/403/400 拒绝，且每次尝试（含拒绝）在 da_console_query_log 有记录、SQL 仅存前 4KB 摘要 + SHA-256。
AC-6  [注册表扩展]  Given 未授权用户查询源列表, Then 仅返回 t_ds_relation_datasource_user 授权范围（管理员全量）；da_console 对 console.enabled=false 的实例整体 404。
AC-7  [边界]        Given 空结果集、全 NULL 列、中文内容, When 查询, Then 类型与编码正确返回；JSON 包体形状与现有 data-api 一致。
AC-8  [非功能]      Given 查询台运行, Then 不新增 DS 反应堆构建负担（DS 其余模块 reactor 构建不受影响）；元库连接 ≤5、单业务源池 ≤5。
```

AC 共 8 条 → testing-strategy 用例下限按 §9.2 的 9 正向 + 8 拒绝覆盖并回连到 AC。

## Assumptions（无追问澄清项）

1. 方案文档即用户确认的需求基线；"P2/P3 中 DataSourcePluginManager 替换与注册表合并实施"按分析结论执行，不做过渡实现。
2. 开发默认连线上 PG（123.57.2.64）；若网络不可达，测试层用 H2 PG 兼容模式 / Testcontainers 替代，不阻断验收。
3. 首批描述符只做 postgresql + mysql（方案 P3 验收所需），其余 26 类按需后补。
4. 前端沿用 UI 内现有 data-api 视图的鉴权与请求封装；不引入新 UI 框架依赖（CodeMirror 6 若 UI 已有则复用）。
5. 生产不启用查询台（D4），`console.enabled` 默认 false。

## Implementation Path

## 实施偏差记录（2026-11-06，实现阶段确认）

1. **Boot 版本**：方案 §5 与工程约束附录写的是 Spring Boot 2.6.1，实际按迁移目标选择 **3.0.13**（spring-boot-starter-parent，jakarta 命名空间）。2.6.1 仅适用于留在 DS 反应堆内的旧线，不构成本模块契约。
2. **Servlet API 钉版**：Boot 3.0.13 BOM 默认 `jakarta.servlet 6.0.0`，但 starter-jetty 带的 Jetty 11.0.18 仍引用 Servlet 6.0 已删除的 `HttpSessionContext`，会在创建 Web 服务器时抛 `NoClassErrorDefFound`。已在模块 pom 显式覆盖属性 `jakarta-servlet.version=5.0.0`（Jetty 11 = Servlet 5.1 线）。
3. **编辑器组件**：方案 §7.4 建议 CodeMirror 6，UI 现状是全局 Monaco（`@/components/monaco-editor`，已在依赖内）。按"不引入新 UI 框架依赖"原则（Assumption 4）复用 Monaco，Ctrl/Cmd+Enter 触发运行。
4. **前端类型检查**：`vue-tsc@0.40 + TS@4.8` 在本环境对大量未改动文件报系统性 TS7026（JSX）错误，属既有工具链问题；以 `pnpm exec vite build --mode production` 成功（console 视图进入产物）作为构建验证替代。
5. **JDK 17 运行线**：data-api 构建/启动脚本全部切换：`start-local.sh` 新增 `API_JAVA_HOME`（默认取 `ASSET_JAVA_HOME`），`start-local.ps1` 新增 `-ApiJavaHome`；all-in-one 镜像在 temurin-11 基础上新装 `openjdk-17-jre-headless`，`run-data-api.sh` 用 `API_JAVA` 显式指向 17，DS/SeaTunnel 仍走 11。
6. **冒烟环境数据**：P0/P4 联调在开发 PG 元库追加了两条数据（`t_ds_datasource` 演示源 `agri_sat` id=1、`da_datasource_ext.console_enabled=1`），为环境状态，不随代码提交；`connection_params` 需含 `"user"` 字段这一契约已由 loader 读侧验证。
